# Cloudflare Workers Compatibility Spike Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Select a safe Cloudflare Workers adapter and prove the Client 1 application works in a non-production Worker before any traffic moves.

**Architecture:** Start with a non-destructive vinext compatibility check. If it has a P0 blocker, evaluate OpenNext instead. Deploy only an isolated preview backed by a dedicated preview Supabase project and Hyperdrive; the output is a recorded READY_FOR_PRODUCTION_PLAN or BLOCKED decision.

**Tech Stack:** Next.js 16, Cloudflare Workers, vinext/OpenNext, Wrangler, Hyperdrive, Supabase Auth/PostgreSQL, GitHub Actions.

**Spec:** docs/superpowers/specs/2026-08-28-client1-pwa-cloudflare-design.md

## Global Constraints

- Do not change production DNS, production Supabase redirects, or production traffic.
- Use a dedicated preview Supabase project and non-production Cloudflare secrets only.
- Keep current npm dev, build, and start scripts working while the spike runs.
- Do not migrate to D1 or replace Supabase Auth in this spike.
- The selected adapter must pass every P0 check; otherwise the spike is blocked.

### Task 4: Deploy and close the spike on evidence

**Files:**
- Create: .github/workflows/cloudflare-preview.yml
- Modify: docs/runbooks/cloudflare-workers-spike.md

**Interfaces:**
- workflow_dispatch deploys only through a protected cloudflare-preview GitHub environment.
- Result is exactly READY_FOR_PRODUCTION_PLAN or BLOCKED.

- [ ] **Step 1: Add the manual preview workflow**

~~~yaml
name: Cloudflare preview
on: { workflow_dispatch: {} }
jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: cloudflare-preview
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22, cache: npm }
      - run: npm ci
      - run: npm run build:cloudflare
      - run: npm run deploy:cloudflare
        env:
          CLOUDFLARE_API_TOKEN: \${{ secrets.CLOUDFLARE_API_TOKEN }}
~~~

- [ ] **Step 2: Deploy and execute every P0 row**

Dispatch the workflow from a known commit, verify it prints a preview URL, then execute and record every P0 row. Capture timestamp, route, role, expected/actual outcome, and Worker log reference.

- [ ] **Step 3: Apply the decision rule**

Set READY_FOR_PRODUCTION_PLAN only if every P0 test passes, no runtime compatibility error is in Worker logs, and no production secret was used. Otherwise set BLOCKED and include each failing command and log reference.

- [ ] **Step 4: Verify the existing application and commit**

Run: npm run lint && npx tsc --noEmit && npm test && npm run build

Expected: all commands exit 0.

~~~bash
git add .github/workflows/cloudflare-preview.yml docs/runbooks/cloudflare-workers-spike.md
git commit -m "docs(cloudflare): conclude workers compatibility spike"
~~~

If READY_FOR_PRODUCTION_PLAN, create a new production-migration plan with the selected adapter, exact bindings, custom-domain cutover, rollback, and client acceptance tests. Do not move production traffic in this spike.
