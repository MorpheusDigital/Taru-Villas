# Client 1 PWA v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Make the portal installable on iOS and Android, retain Fleet push notifications, and clearly explain that online workflows require connectivity.

**Architecture:** Emit a Next.js manifest, globally register the existing single service worker inside authenticated portal pages, and cache only static application assets. No API data, form data, photos, uploads, or authenticated records are cached or queued.

**Tech Stack:** Next.js 16 App Router metadata routes, React 19, TypeScript, Service Worker APIs, Vitest.

**Spec:** docs/superpowers/specs/2026-08-28-client1-pwa-cloudflare-design.md

## Global Constraints

- PWA v1 is online-first. Offline drafts, queued media, and resumable sync are explicitly out of scope.
- Retain one worker at /sw.js; never create a second worker.
- Build-time identity uses NEXT_PUBLIC_APP_NAME, NEXT_PUBLIC_APP_SHORT_NAME, and NEXT_PUBLIC_THEME_COLOR.
- Before Client 1 production build, provide public/icon-192.png and public/icon-512.png from approved client branding.

### Task 3: Apply static-only cache rules and worker update headers

**Files:**
- Create: src/lib/pwa/cache-policy.ts
- Create: src/lib/pwa/cache-policy.test.ts
- Modify: public/sw.js
- Modify: next.config.ts

**Interfaces:**
- shouldCacheStaticPath(pathname: string, method: string): boolean.
- Only same-origin GET paths beginning /_next/static/ or matching /icon- or /TVPL.png qualify.

- [ ] **Step 1: Write the failing cache boundary test**

~~~ts
import { expect, it } from 'vitest'
import { shouldCacheStaticPath } from './cache-policy'

it('allows static assets and rejects data paths', () => {
  expect(shouldCacheStaticPath('/_next/static/chunks/app.js', 'GET')).toBe(true)
  expect(shouldCacheStaticPath('/icon-192.png', 'GET')).toBe(true)
  expect(shouldCacheStaticPath('/api/tasks', 'GET')).toBe(false)
  expect(shouldCacheStaticPath('/dashboard', 'GET')).toBe(false)
  expect(shouldCacheStaticPath('/api/fleet/requests', 'POST')).toBe(false)
})
~~~

- [ ] **Step 2: Run it to verify it fails**

Run: npx vitest run src/lib/pwa/cache-policy.test.ts

Expected: FAIL because cache-policy is absent.

- [ ] **Step 3: Implement policy and matching service-worker behavior**

Implement the exact predicate above. In sw.js, define one cache name such as taru-static-v1. For a fetch event, only handle same-origin GET requests whose pathname obeys the predicate; return cache-first and cache a successful network response. Do not handle navigation, /api, or non-GET requests. On activate, delete every cache except the current cache before clients.claim(). Add the message handler:

~~~js
self.addEventListener('message', (event) => {
  if (event.data?.type === 'SKIP_WAITING') self.skipWaiting()
})
~~~

- [ ] **Step 4: Send no-cache headers for the worker script**

Add headers() in next.config.ts containing this /sw.js rule:

~~~ts
{
  source: '/sw.js',
  headers: [
    { key: 'Cache-Control', value: 'no-cache, no-store, must-revalidate' },
    { key: 'Service-Worker-Allowed', value: '/' },
  ],
}
~~~
